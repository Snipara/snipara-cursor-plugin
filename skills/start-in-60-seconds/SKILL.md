# Start Snipara in 60 Seconds

Use this skill to move a Cursor user from plugin install to usable project context.

## Boundary

Snipara has two startup paths:

- Local-first bootstrap: no account required for local activation artifacts, repo scan signals, First Work Brief material, and client instructions generated by `create-snipara`.
- Hosted memory and retrieval: requires a free Snipara account and `SNIPARA_API_KEY` so Cursor can connect to `https://api.snipara.com/mcp/snipara`.

Do not imply that hosted MCP memory works without an API key. Do not use legacy internal environment variable names in public Cursor setup instructions.

## Fast Path

1. If `SNIPARA_API_KEY` is present, use the bundled hosted MCP server and continue with `first-work-brief` or `project-memory`.
2. If no key is present, offer the local starter command:

   ```bash
   npx create-snipara@latest init --client cursor --starter
   ```

3. Explain that this creates project-local Snipara guidance, Cursor rules, activation artifacts, and a First Work Brief path from the current repository.
4. If the user wants local workflow helpers after first value, use:

   ```bash
   npx create-snipara@latest init --client cursor --profile hosted-companion --starter
   ```

5. If the user explicitly wants no hosted API path at all, use:

   ```bash
   npx create-snipara@latest init --client cursor --profile runtime-only --starter
   ```

## After Setup

Ask Cursor to read the generated project instructions before continuing:

- `.cursor/rules/snipara.mdc`
- `.snipara/activation/first-work-brief.md` when present
- `.snipara/activation/manifest.json` when present
- `.snipara/README.md` when present

Then produce a concise answer with:

- what Snipara can do locally now
- what unlocks when `SNIPARA_API_KEY` is added
- the next useful agent prompt for the repository
